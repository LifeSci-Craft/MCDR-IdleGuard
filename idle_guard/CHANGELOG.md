## v1.2.0

没有新增功能：改动集中在"出问题时不能静默失效"（几处既不给玩家提示、也不留日志的地方）、
多实例下的状态一致性，以及仓库的工程约束。

### 变更

- **对远端子服的 `sleep` / `wake`：执行前检查只对「本实例自己负责」的子服下结论。**
  本实例不再用心跳缓存替别的实例判断该不该动它，远端请求一律转给负责它的实例、由那边用权威状态回话。
  影响：远端请求的回复可能比"立刻回绝"晚一点，但不会再出现"本该执行的唤醒被旧状态挡掉"；
  本实例自己负责的子服行为不变。
- **对远端目标不再先说「正在启动…」**：那句话可能立刻被真相反驳（例如它其实已经在运行）。
  远端请求的第一句回复就是负责方的结论；本地子服仍会先说一句再执行。
- **首次生成配置时日志只打印总线口令的 8 位指纹**，不再打印口令本身。
- **假服务端连接数超限时不再静默丢弃**：仍记一次"有人在连"（照常触发自动唤醒）并留一条限流日志，
  再关连接；正常上限之外另有 16 条"短预算"名额，尽量让真人玩家收到那句休眠提示。
  同一来源 IP 另有独立名额。
- **唤醒冷却只在"上一次尝试仍在进行"时生效**：启动失败后不再挡住玩家 15 秒内的重试。
- 状态表里的子服编号改为与命令解析口径一致；配置出现重名条目时，两行不再显示成同一个编号。

### 修复

- **配置里写错端口不再让插件加载不起来**：`bus.bind` 或 `servers[].bus` 里超出 1..65535 的值
  现在按非法地址处理（总线不启动、日志说明原因、`!!ig check` 会列出），不再抛 `OverflowError`
  穿透 `on_load` 并留下半初始化的后台线程。
- **读命令不再向对端发网络请求**：`!!ig status / diag / check` 只用心跳留下的快照。
  对端被防火墙丢包时，以前会把 MCDR 的命令线程卡到十几秒（把 `state_tick` 设为 0 时每次命令都卡）；
  没有新鲜快照的行现在退回本地旧快照并标记为不可信，探测交给后台心跳。
- **统计文件改为原子写盘**（临时文件 + 替换）：崩溃或并发写不再可能留下半个 JSON 而被整份丢弃，
  读不动的旧文件会改名成 `stats.json.corrupt` 留证。
- **纯 `role=command` 的部署里"服务端正在备份"的保护以前完全失效**，现在覆盖所有由本实例启停的子服。
- **`role=command` 的启停命令会回收子进程并报告失败**（命令不存在或立刻退出会记一条 error），
  stdin / stdout / stderr 不再继承 MCDR 的控制台。
- **对端快照里未知的 `role` / `state` 会被降级**（`watch` / `unknown`）；同一子服被两台实例
  同时认领时只信最先报上来的那台。
- **协议层边界收紧**：`pack_packet` 增加出站长度校验；`decode_varint` 按协议只接受最多 5 字节 / 32 位。
- 语言文件：英文 `state.offline` 由 `stopped` 改成 `not running`；英文 `hover.note.offline`
  补上 `{server}`；删掉一个从未被引用的死键。

### 内部整理

- **仓库不再提交打包产物**（`.gitignore` 覆盖 `idle_guard-*.mcdr`）。
- **总线加固**：总连接数与每 IP 连接数都有上限（超限记 warning 并关连接）；鉴权通过之前只允许
  读 4 KiB；口令改用常量时间比较；握手期的连接异常会记一条 debug 日志。
- **端口接管与唤醒之间补了一次 bind 前的状态复查**；插件卸载过程中不再把端口抢回来；
  `shutdown` 等轮询线程的上限从 3 秒提到 20 秒。
- **状态探测线程池改为常驻**（以前每个心跳周期新建一个）。
- 假服务端 backlog 提到不小于并发上限；接受成功即清掉上一次的接受错误。
- 写回 `config.json` 时保留文件里本插件不认识的键。
- **新增仓库根 `ruff.toml`**（只启用 E9 + F 两组规则），并清掉它报出的 18 处问题。
- **CI 增加三个作业**：ruff 静态检查、钉死最低支持的 MCDR（2.13.0）跑测试 + 压测 smoke、
  跨 MCDR 版本矩阵（2.13.0 / 2.14.1 / 2.15.0 / 2.15.7 / 2.16.0）。
- `tools/check_artifact.py` 增加 `id`、`author`、产物版本与源码 `PLUGIN_VERSION` 的一致性断言，
  加上源码与产物的白名单差集检查、逐成员内容哈希比对。
- `tools/mcdr_matrix.py` 的最低 MCDR 版本改为从插件元数据解析；找不到"低于最低版本"的环境时
  默认失败（可用 `--allow-missing-low-env` 显式跳过）。
- 修好 `tools/soak.py`（构造配置会直接 `TypeError`，该工具此前无法运行），
  泄漏判定改为丢弃预热轮次后比较首尾趋势；`tools/*.py` 的 stdout / stderr 显式设为 UTF-8。
- README 的 Python 徽章改为 `>=3.9`（MCDR 2.15 / 2.16 的 `Requires-Python` 是 3.9 起）；
  `docs/DEVELOPMENT.md` 的测试数量与真机端到端结论更新为本次实测，并补上
  "仓库内全文检索请用 `git grep`"的提醒。
- 用户配置样例 `user-config/idle_guard-config.json` 里的总线口令替换为占位符
  （该值此前存在于公开仓库的历史中，请在各实例上轮换）。

### 验证

- 测试 **349 项**全部通过（`python -m pytest tests/`），其中 40 项为本次修复新增的回归测试。
- 跨版本矩阵：MCDR 2.13.0 / 2.14.1 / 2.15.0 / 2.15.7 / 2.16.0 各起一个真实 MCDR，
  跑 `!!ig help` / `!!ig status` / `!!ig reload` 全部通过；2.12.0（低于最低版本）被依赖检查干净拒绝。
- 真机端到端（Velocity + 2×Paper 1.21.4 + 2 个 MCDR + mineflayer 假玩家）：**38/41**。
  未通过的 3 项：①「休眠预告」对应的是 v1.1.0 已删除的功能（场景断言过时）；
  ② 远端子服的 `sleep` 现在由负责方判断，所以会先给确认提示；③ 一项日志取样撞到假玩家的死亡消息（场景噪声）。
- 产物自检：同一源码两次打包逐成员内容哈希一致（整包字节也一致）、内容白名单、无漏包、
  注释与 docstring 已剥离且仍可编译、元数据与源码版本一致。
- `ruff check .` 与 `python tools/soak.py --rounds 20` 通过。
