## v1.0.0

首个版本。群组服的子服在连续无人后自动休眠，玩家连接时自动唤醒；休眠期间由假服务端顶替端口，
所以服务器列表与玩家连接都能得到回应。

### 新增

- **自动休眠**：按 `check_interval`（默认 10 分钟）用协议层状态查询侦察人数，连续无人到
  `idle_timeout`（默认 1 小时）后让 MCDR 关掉该子服。阈值可全局设，也可按子服单独设。
- **假服务端顶替端口**：休眠期间顶替该端口，服务器列表里显示「已休眠」，玩家连接会收到自定义提示
  （含预计启动时间）并触发自动启动；就绪后广播「已开启（耗时 xx 秒）」，单独提醒那位玩家，可带音效。
- **跨实例总线**：各子服的 MCDR 通过 TCP 互发消息，实现跨服通知与跨实例启停；`role: auto` 搭配
  `bus.bind: "auto"` 让同一份配置可直接复制到每台实例。
- **命令**：`!!ig status` / `sleep` / `wake` / `lock` / `unlock` / `confirm` / `cancel` / `poll` / `reload`；
  子服参数可写编号（配置顺序）或名字，控制台支持 Tab 补全。
- **安全检查**：`!!ig sleep` 需 `!!ig confirm` 二次确认（30 秒内有效，按发起人隔离）；
  有玩家在线或人数无法确认时拒绝休眠；连续启动失败 3 次自动锁定，需 `!!ig unlock` 放行。
- **权限**：全部命令默认要求 admin（级别 3）。放行某人请在 MCDR 的 `permission.yml` 里把他的等级
  提上去（名字大小写敏感），要放宽某条命令的门槛则改插件里的权限常量。
- **多语言**：文案全在 `lang/zh_cn.json` / `lang/en_us.json`，配置里只有行为开关；`language: auto`
  跟随 MCDR，也可在 `config/idle_guard/lang/` 覆盖内置文案，升级不覆盖。
- **常驻子服**：`servers[].always_on` 给"希望长期开着"的子服一个总开关。打开后自动判定不会关它，
  管理员手敲的 `!!ig sleep`（包括从别的实例发来的）也会被直接拒绝；状态表的开关列显示「常驻」，
  鼠标移上去能看到原因。
- **从 Velocity 同步子服清单**：`velocity_config`（默认 `"auto"`）会在启动时读 `velocity.toml` 的
  `[servers]` 段，把**还没写进 `servers[]`** 的子服补进来（名字 / 地址 / 端口），结果写回
  `config.json`。已有条目一律不动（`role` / `auto_sleep` / `always_on` / `bus` 是你手写的），
  地址对不上只在控制台提醒；找不到文件就安静跳过，`"off"` 可关闭这个功能。
- **`!!ig diag` 诊断页**：一条命令说清「谁认领了谁、总线与对端健不健康、为什么还不休眠、ETA 样本、
  最近状态变化」。以前这些只能翻日志猜。
- **`!!ig stats` 统计**：每个子服的休眠次数、累计休眠时长、唤醒次数（落盘，重载不丢）。
- **服务端忙时不休眠**：命中 `busy_patterns`（默认覆盖常见备份插件文案）就延后一轮自动休眠，
  免得备份跑到一半被打断；`busy_hold_seconds`（默认 300 秒）到点自动失效。手动 `!!ig sleep` 不受限。
- **ETA 分冷 / 热启动**：样本同时记录「距上次停止过了多久」，停机很快又唤醒（默认 5 分钟内）时
  用热启动样本的中位数，报给玩家的秒数更贴近实际。
- **状态心跳** `state_tick`（默认 5 秒）：只查本实例负责的子服，让「刚关 / 刚开」几秒内就反映到界面。

### 修复

- **玩家退出后插件仍认为他在线**，导致空闲计时不开始、`!!ig sleep` 被一直拒绝：MCDR 对
  `X left the game` 用的是严格整行匹配，而新版服务端打印的是 `System chat: X left the game`，
  离开事件因此从未触发。现在插件自己解析服务端输出的进 / 退消息（含 `lost connection`，
  玩家聊天行不参与），并以状态查询兜底自愈（连续 60 秒报 0 人在线才清掉那个名字）。
- **在别的子服敲 `!!ig sleep <那台服>` 只看到「正在休眠…」、很久之后才「等待超时」**：远程请求
  此前先回「已受理」再转后台，拒绝理由只留在对端日志里。现在转后台前先同步判一次能不能休眠，
  「还有人在这台服上」这类原因会立刻回到玩家那边。
- **关服后状态表仍写「运行中」、开好后一直写「启动中」**：状态只在侦察周期里更新。现在有心跳、
  MCDR 报告启动完成时立即置「运行中」，并就绪判定增加「进程活着且端口可连」的兜底。
- **在后台敲 `stop` 关服被当成了「休眠」**：状态表显示「已休眠」、假服务端把端口占住、控制台还提示
  「将保持休眠状态」，而且插件清掉了 MCDR 的 `EXIT_AFTER_STOP` 标记，于是 `stop` 再也关不掉整个
  实例。现在按退出码区分：正常退出（返回码 0）记为「已停止」，不接管端口、不碰标记、通知也写明
  「不是休眠」；只有异常退出（崩溃 / 被强杀）才走原来的兜底（假服务端接管 + 留住 MCDR）。
- **分不清「没人管它」与「管它的实例掉线了」**：以前状态表里这两种情况长得一模一样（都是
  「只监视」+ 备注 `-`），管理员不知道该去启动哪台 MCDR。现在心跳会持续探测对端实例，联系不上时
  备注显示红色的 `@实例名(离线)`，`!!ig diag` 里还能看到具体失败原因（连不上 / 鉴权失败 / 没应答）。
- **连接休眠中的子服、被唤醒后玩家什么提示都收不到**：他那一刻已经被假服务端挡回客户端，不在任何
  服务端里。唤醒完成的广播是在服务端内部说的（他看不到），单独 tell 又因为"玩家不在线"被丢掉。
  现在会把这几位玩家记下来，等他们真正进服时补一条「已开启」并附带音效（超过 10 分钟才进来就不补了）。
- **预计开服时间不准**：以前照搬"上一次"的实测耗时，而启动耗时抖动很大（世界加载、mod 初始化、
  磁盘缓存冷热），经常差出好几倍。现在保留每台服最近 8 次实测并报其中位数，个别离谱样本不会把
  估计带跑；旧版留下的是单个数字，也能直接读，不用手动改文件。
- **跨实例操作的提示文不对题**：`role` 本来就是 `auto` 时，回复还在劝"把它的 role 改成 auto 或 self"，
  照着改也不会有任何变化（线上真踩到过）。现在按角色分两种说明：`auto` 时指向"端口与它一致的那台
  实例没有应答（没运行 / 没装本插件 / 总线地址没配对）"，只有配置成 `watch` 之类时才提示去改 role。
  同时"没有任何实例应答"会写进控制台日志，带上试过的地址与各自的失败原因，不再只留一句无从查起的话。
- **总线的接受线程遇到意外错误会永久停摆**：socket 还留在 LISTEN 状态，对端连得上、消息也发得出去，
  但永远等不到应答，在对方看来就是"那台实例不在线"。现在记一条日志、隔一秒继续接受连接。
- **服务端崩溃会让 MCDR 一起退出**（MCDR 的 `EXIT_AFTER_STOP` 语义），假服务端随之消失：
  异常退出分支里清除该标记。
- **「空闲」信息不显示**：空闲计时此前与 `auto_sleep` 绑在一起，关掉自动休眠的子服根本不计时。
  现在照常计时，信息放在状态表的悬停浮窗里。
- **远端子服的角色显示成「本实例」**：远端上报的 `role: self` 含义是对方负责，现显示为「对方实例」。
- **给玩家报的预计启动时间与实际出入大**：改用上一次实测耗时（落盘复用），实测与估计吻合。
- **重复操作没有提醒**：已在目标状态 / 正在变动 / 有人在线时直接回话，不再做无意义动作，也不再
  对自己广播导致「本实例不负责 X」的误报。
- **命令回调阻塞**：休眠与唤醒转到后台线程，先回「正在执行…」再补结果，不再触发 MCDR 的
  「线程十秒没有响应」。
- **通知前缀颜色不统一**：`[Idle Guard]` 统一为天蓝色。
- **玩家名可能被注入**：来自客户端握手的名字经 `^[A-Za-z0-9_]{1,16}$` 过滤后才拼进命令。

### 内部整理

- 纯 Python 实现，除 MCDR 自身依赖外零第三方包。
- 打包可复现（固定 zip 时间戳、剥离注释与 docstring），包内只带 `CHANGELOG.md`、`LICENSE`、
  元数据、`lang/*.json` 与代码。
- README 只留用户向内容（功能 / 安装 / 命令 / 配置 / 注意），实现细节移到 `docs/DEVELOPMENT.md`；
  另有一份英文版 `README_en.md`，两份互相链接。
- 按主题拆模块：`models.py`（数据结构）、`takeover.py`（假服务端与端口接管）、`remote.py`（跨实例总线）、
  `diag.py`（诊断页）、`stats.py`（统计）、`velocity.py`（读 velocity.toml）。主控仍在 `supervisor.py`。
- 加了 GitHub Actions：每次推送与 PR 跑单元测试、打包与产物自检（Python 3.9 / 3.12 / 3.13）。
